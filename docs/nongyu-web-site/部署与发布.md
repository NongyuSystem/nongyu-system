## 1. 目标与原则

### 1.1 目标

- 公网 **HTTPS** 访问：官网 `https://<域名>/`，管理端 `https://<域名>/admin/`（须安全组放行 443）
- 在 443 未放行前，**HTTP `:80` 继续提供业务**（只保留 ACME 路径）；放行后再把 `:80` 改为 301
- GitHub Actions（或本机脚本）构建 Vite `dist`，上传覆盖远端目录；服务器不装 pnpm、不编译前端
- 管理端 API 走同机 Nginx 反代 `/api` → Node 业务机（避免浏览器跨域）

### 1.2 硬约束

| 项     | 约定                                                                                 |
| ------ | ------------------------------------------------------------------------------------ |
| 发布物 | Ubuntu runner 或本机 `pnpm --filter … build` 产物；只上传 `dist` 内容                |
| 进程   | 仅 Nginx 提供静态文件；无 Node 跑前端                                                |
| TLS    | Let’s Encrypt **域名证书**（约 90 天）；acme.sh 自动续期后 `systemctl restart nginx` |
| 敏感   | IP / SSH 口令 / `web-deploy.env` **不进 git**                                        |
| 共存   | 不得覆盖/删除 ACME 或其它业务目录；本机目录独立于 Node 机                            |

### 1.3 非目标

- 为 WEB 公网 IP 另签 IP 短寿证书（`https://<IP>` 会证书名不匹配，请用域名）
- 在服务器上构建前端
- 把 Node / Track **强制绑成一次全量发布**（四端按路径独立 job）
- 本机保存文件即自动发布（须 push 到 `main` 或手动 Run workflow）

## 2. 拓扑

```text
公网客户端
    │  HTTPS  https://<域名>/
    │         https://<域名>/admin/
    │  HTTP   :80 → ACME + 301 https://<域名>
    ▼
Nginx（本机 WEB 机）
    ├─ /                → /var/www/site/          （官网 dist）
    ├─ /admin/          → /var/www/admin/         （管理端 dist，Vite base=/admin/）
    ├─ /api/            → proxy → <NODE_UPSTREAM> （Node 业务机，如 http://8.x.x.x）
    └─ /v1/track/web/   → proxy → <TRACK_UPSTREAM>
```

说明：当前 WEB 机与 Node 机可为两台；`/api` 反代地址写在服务器 Nginx 与本机 `web-deploy.env` 的 `WEB_API_UPSTREAM`。

---

## 2.1 HTTPS / 域名证书

与 Node/Track 的 **IP 短寿证**不同：官网有真实域名，走 Let’s Encrypt **普通域名证书**（约 90 天）。

| 项       | 现网约定                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 证书名   | 规范域名 + `www`（同一张证）                                                                                   |
| 校验     | HTTP-01（webroot `/var/www/acme`）；**80 必须对公网开放**                                                      |
| 客户端   | `/root/.acme.sh/acme.sh`                                                                                       |
| 证书文件 | `/etc/nginx/certs/<域名>.fullchain.pem` 与 `.key`                                                              |
| 续期     | crontab 每 6 小时 `acme.sh --cron`；输出 `/var/log/acme-cron.log`；成功后 `nginx -t && systemctl reload nginx` |
| 防火墙   | 公网 **80、443**（腾讯云安全组与机上 iptables 都要放行）                                                       |

签发（示意）：

```bash
/root/.acme.sh/acme.sh --issue -d <域名> -d www.<域名> -w /var/www/acme --keylength 2048
/root/.acme.sh/acme.sh --install-cert -d <域名> \
  --fullchain-file /etc/nginx/certs/<域名>.fullchain.pem \
  --key-file /etc/nginx/certs/<域名>.key \
  --reloadcmd "nginx -t && systemctl reload nginx"
```

**续期失败常见原因**：安全组关掉 80、Nginx 去掉 `/.well-known/acme-challenge/`、磁盘满。先看 `/var/log/acme-cron.log`。

## 3. 路径与 SPA

| 路径      | 应用               | 构建约定                                        |
| --------- | ------------------ | ----------------------------------------------- |
| `/`       | `nongyu-web-site`  | Vite 默认 `base: /`                             |
| `/admin/` | `nongyu-web-admin` | 生产 `base: /admin/` + `BrowserRouter` basename |

管理端本地 `vite` 开发仍用 `base: /`（访问 `http://localhost:5173/`），仅 `build` 使用 `/admin/`。

## 4. 日常发布

日常：本机 CR / husky 后 `git push origin main`。官网路径有变更则只发官网，管理端（含其 workspace Agent 依赖）有变更则只发管理端。约定见 [`docs/common/GitHub持续交付.md`](../common/GitHub持续交付.md)。

应急（断网或 Secrets 未配）：

```text
本机改代码 → 手工验
  → powershell -File scripts/deploy-nongyu-web.ps1
  → 本机构建 site + admin → 打包上传 → 远端解压覆盖 → nginx -t && reload
```

参数：

| 参数          | 含义                      |
| ------------- | ------------------------- |
| `-SkipBuild`  | 跳过构建，只上传已有 dist |
| `-SiteOnly`   | 只发布官网                |
| `-AdminOnly`  | 只发布管理端              |
| `-SkipReload` | 不执行 `nginx -s reload`  |

首次装机或改 Nginx 样例后：把 `docs/nongyu-web-site/deploy/nongyu-web.nginx.conf.example` 落到服务器并 `nginx -t && systemctl reload nginx`（脚本在检测到需装机时可辅助执行；日常发布默认只覆盖静态文件）。
