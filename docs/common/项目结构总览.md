# 农屿系统 · 项目结构总览

> Agent 用：了解 monorepo **顶层文件布局与各目录职责**。粒度止于 `apps/`* / `packages/*` 一级，不展开各包内部源码树。  
> 深入某个包的调用关系 / 符号定位，优先走 CodeGraph；精确字符串用 Grep。详见 `.agents/rules/代码检索策略.md`。

## 仓库树（一级）

```text
nongyu-system/
├── AGENTS.md                 # Agent 宪法级入口（地图：只指路，不堆细则）
├── README.md                 # 人类可读总览；Agent 非必要不加载
├── package.json              # 根 workspace 脚本与公共开发依赖
├── pnpm-workspace.yaml       # monorepo 成员：apps/*、packages/* + catalog
├── pnpm-lock.yaml
├── tsconfig.base.json        # 共享 TS 基座配置
├── commitlint.config.mjs
├── .github/                  # GitHub Actions 持续交付（四端按路径自动发布）
├── .husky/                   # git hooks（commit 前 lint / commitlint）
├── .agents/                  # Agent harness：rules、skills
├── .cursor/                  # Cursor 本地配置（如 Bugbot 规则）；勿当业务源码
├── .codegraph/               # CodeGraph 本机索引（gitignore，勿提交）
├── apps/                     # 可交付产品应用
├── packages/                 # 可复用工具库 / Agent 相关包
├── design-system/            # 各端 UI 设计准则（MASTER.md）
├── docs/                     # 文档库（common / 分项目 / forhuman）
├── scripts/                  # 本机应急发布（ops/ 凭据 gitignore）与 CD 远端脚本（scripts/cd/）
└── old-code/                 # 旧项目归档入口（见下文；勿当现行实现源）
```

## 目录职责

| 路径             | 职责                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| `apps/`          | 面向用户或服务端的**产品应用**；日常业务与基建实现主要落在此            |
| `packages/`      | 跨应用复用的**库与工具**（Agent SDK/CLI/GUI、教务/二课工具等）          |
| `design-system/` | 各端视觉与交互定调；写/改 UI 前按端加载对应 `MASTER.md`                 |
| `docs/`          | Spec / 技术方案 / 计划 / 全局策略；写法见文档库管理策略                 |
| `.agents/`       | Coding Agent 规则与 Skills；**不是**业务运行时代码                      |
| `old-code/`      | 历史实现归档；仅对照/迁移时查阅，**禁止**当作现行源码直接改或引用为真相 |

## 旧项目在哪里找

- **位置**：仓库根目录 `old-code/`（**已列入 .gitignore，不随仓库分发**）。接手者本机若没有该目录，说明旧码仍在交接方手里，需单独索取或明确丢弃。
- **用途**：迁移对照、查历史行为、核对旧接口/页面；**不是**当前 monorepo 的实现真相。
- **Agent 约束**：
  1. 默认不要把 `old-code/` 当现行代码库去改、去依赖、去复制进 `apps/`/`packages/`（除非用户明确要求迁移/对照）。
  2. 需要对照时，只进入 `old-code/` 下与任务相关的子目录，**不要**把整棵旧树读进上下文。
  3. 旧树顶层子目录（仅作路标，细节不纳入本总览）：

```text
old-code/
├── nongyu/                   # 旧主应用相关
├── nongyu-admin/             # 旧管理端
├── nongyu-website/           # 旧官网
├── nongyu-server/            # 旧服务端
├── nongyu-agent/             # 旧 Agent 相关
├── nongyu-agent-cli/         # 旧 Agent CLI
└── nongyu-jiaowu/            # 旧教务相关
```

现行实现请在 `apps/`、`packages/` 中定位；文档与 Spec 在 `docs/`。

## Agent 使用提示

1. 先用本文件确认「改哪个 app/package」，再下钻该目录。
2. 架构约定到此为止；包内模块结构用 CodeGraph / 该包自有文档，避免在本文件堆深层树。
3. 本文件随仓库布局变更维护；增删 app/package 时同步更新本节。
