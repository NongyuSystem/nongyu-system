## 1. 目标与原则

### 1.1 目标

- Node 跑在 **已有线上 MySQL 的同一台机器**上，只连本机/回环 MySQL，不另开数据库实例、不改现网库结构除非显式跑迁移
- 公网只暴露 **Nginx :443**（及 ACME 用的 :80）；Node 不直接对公网监听
- 对外访问形态：`https://<公网IP>/...`（无域名）
- `main` 上 Node 目录有变更时，GitHub CD 构建 Linux `dist`、覆盖远端并 **systemd 重启 + /health 回滚**；本机脚本仍可应急

### 1.2 硬约束

| 项            | 约定                                                                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 与 MySQL      | **同机**；`MYSQL_HOST=127.0.0.1`；禁止对公网开放 3306；部署脚本**不得**重启/重装/覆盖 MySQL                                                  |
| 发布物        | GitHub Ubuntu（或本机）`tsup` 产物 `dist/` + 远端 `npm install --omit=dev`（**禁止**拷 `node_modules`）                                      |
| 进程          | systemd 单元 `nongyu-node.service`；`node dist/index.js`；**不用** PM2、不用远端 `tsx watch`                                                 |
| TLS           | Nginx 终止；Let’s Encrypt **IP 证书**（shortlived，约 6 天，必须自动续期）                                                                   |
| 监听          | Node 仅 `127.0.0.1:3000`；Nginx `proxy_pass` 到该地址                                                                                        |
| Nginx IP 限流 | `limit_req`：`10r/s` + `burst=30`，超限 `429`；ACME/`/health` 不限流；进程内登录等局部限流保留（见 `deploy/nongyu-node.nginx.conf.example`） |
| 敏感          | IP / SSH / `.env` 口令 **不进 git**                                                                                                          |
| `.env`        | 只在服务器维护；日常发布**不同步**本机 `.env`                                                                                                |

### 1.3 非目标（本期）

- 本机保存文件即自动 rsync（须 push `main` 或手动 dispatch）
- 在服务器上日常编译 TypeScript
- 把 Node 与 Track **强制一次全量发布**（按路径独立 job）
- 为 IP 申请普通 90 天域名证书（IP 证书必须走 shortlived）
- 改动现网 MySQL 账号体系或把 3306 暴露到公网

## 2. 拓扑

```text
公网客户端
    │  HTTPS  https://<公网IP>/
    ▼
Nginx :443（IP 证书）  +  :80（仅 ACME / 可选跳转 443）
    │  HTTP  127.0.0.1:3000
    ▼
nongyu-node-server（systemd）
    │  TCP  127.0.0.1:3306
    ▼
现网 MySQL（已存在，本方案不改其安装）
```

Track 若在**另一台机**：Node 的 `TRACK_BASE_URL` 填 Track 内网或公网可达根地址（无尾斜杠），`INTERNAL_TOKEN` 双方对齐。禁止把 Track 错配成 `127.0.0.1` 除非 Track 也装在本机。

## 3. HTTPS 绑 IP（必读）

Let’s Encrypt 自 2026-01 起可为 **IPv4/IPv6 本身**签发证书。现网实际客户端是 **acme.sh**（机上 Python 3.6 装不了 Certbot 5.4）。

| 项       | 现网约定                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 档案     | ACME `shortlived`；有效期约 **6 天**                                                                                               |
| 校验     | HTTP-01（webroot `/var/www/acme`）                                                                                                 |
| 客户端   | `/root/.acme.sh/acme.sh`                                                                                                           |
| 证书文件 | `/etc/nginx/certs/<公网IP>.fullchain.pem` 与 `.key`                                                                                |
| 续期     | crontab：每天 `0,6,12,18` 点 59 分执行 `acme.sh --cron`；输出 `/var/log/acme-cron.log`；成功后覆盖证书并 `systemctl restart nginx` |
| 防火墙   | 公网 **80、443**；80 必须保留给 ACME（即使业务走 HTTPS）                                                                           |

客户端 Base URL：`https://<公网IP>`（无尾斜杠）。RN：`EXPO_PUBLIC_API_BASE_URL`；Admin：对应 API origin。

## 4. 推荐发布路径（日常）

日常：本机验完后 push `main`，由 [GitHub 持续交付](../common/GitHub持续交付.md) 构建并安全重启。不自动 migrate。

应急：

```text
本机改代码 → 本机 type-check / 手工验
    → powershell -File scripts/deploy-nongyu-node.ps1
    → 打包 dist + package.json 上传
    → （加 -InstallDeps 时）远端 npm install --omit=dev
    → systemctl restart nongyu-node
    → SSH 上回环 curl http://127.0.0.1:3000/health
```

不上传：`.env`、`node_modules`、本机 Windows 编译的原生模块。GitHub CD 每次会上传 `package.json` 并在远端 `npm install --omit=dev`。

### 4.1 何时跑迁移

schema 有新增 SQL 时，**先备份 MySQL**，再在服务器应用目录对**现网库**执行：

```bash
# 远端，工作目录为 /opt/nongyu-node，读取该机 .env
pnpm migrate
# 或：npx tsx 不可用时，用已安装的迁移方式；以服务器实际 Node/pnpm 为准
```

迁移会改现网表结构，必须你显式确认后再跑；日常代码发布默认 **不** migrate。

## 5. 服务器角色（公开描述）

| 项        | 说明                                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------------------------- |
| 角色      | 现网 MySQL 所在机，兼跑 Node + Nginx                                                                                 |

## 7. 装机清单（首次）

在**不中断 MySQL**的前提下：

1. 安装 Node.js LTS（建议 22）与 npm；可选 pnpm。确认 `node -v`。
2. 创建 `/opt/nongyu-node`、`/var/www/acme`；写入 **仅服务器** `.env`（`NODE_ENV=production`、`LISTEN_HOST=127.0.0.1`、`PORT=3000`、`MYSQL_HOST=127.0.0.1`、现网库账号、独立 `JWT_SECRET` 等）。
3. 上传 `package.json` + `dist/`，在目录内 `npm install --omit=dev`。
4. 安装 systemd 单元（见 `deploy/nongyu-node.service.example`），`systemctl enable --now nongyu-node`。
5. 本机 `curl http://127.0.0.1:3000/health` 应 `db=up`。
6. 安装 Nginx；80 提供 ACME webroot；按 `deploy/nongyu-node.nginx.conf.example` 配 443。
7. 用 **acme.sh** 申请 IP 短寿证书（机上 Certbot 太旧）；`--install-cert` 的 reload 为 `nginx -s reload`。细节见技术方案 §5。
8. 安全组 / firewalld：放行 80/443；**保持 3306、3000 不对公网**。
9. 客户端改 Base URL 为 `https://<公网IP>`。

## 8. 安全

1. 禁止把 root 口令、私钥、`node-deploy.env`、服务器 `.env`、`服务器连接信息.md` 提交到 git。
2. Node 崩溃重启由 systemd 负责；不要为了「热更新」把应用目录挂成全世界可写。
3. 生产 `CORS_ORIGIN` **留空**即可（默认禁止浏览器跨域，Admin 走 WEB 机 Nginx `/api` 同源反代）；若 Admin 必须直连 Node HTTPS，填管理端页面 Origin（如 `http://101.43.34.229`），**禁止**长期 `*`。App 走 RN 无浏览器 CORS。
4. 超管默认密码、JWT、LLM 加密密钥必须与开发机不同。
