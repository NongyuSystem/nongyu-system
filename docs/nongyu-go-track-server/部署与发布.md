## 1. 目标与原则

### 1.1 目标

- Track 跑在 **独立轻量云** 上，数据为服务器 SQLite，不碰业务 MySQL
- 公网只暴露 **Nginx :443**（及 ACME 用的 :80）；Track 进程不直接对公网监听
- 对外访问形态：`https://<公网IP>/...`（无域名）
- `main` 上 Node Track / 契约包有变更时，GitHub CD 构建并发布到 `/opt/nongyu-track`，**systemd 重启 + /health 回滚**

### 1.2 硬约束

| 项       | 约定                                                                                        |
| -------- | ------------------------------------------------------------------------------------------- |
| 与 MySQL | Track **不连** MySQL。机上若有 mysqld，部署脚本**不得**重启/重装/覆盖                       |
| 发布物   | Node `dist` + production deps（目标机可对 `better-sqlite3` 执行 `npm rebuild`）             |
| 进程     | systemd 单元 `nongyu-track.service`；**不用** nohup / screen                                |
| TLS      | Nginx 终止；Let’s Encrypt **IP 证书**（shortlived，约 6 天，必须自动续期）                  |
| 监听     | Track 仅 `127.0.0.1:8081`；Nginx `proxy_pass` 到该地址                                      |
| 敏感     | IP / SSH / `.env` 口令 **不进 git**                                                         |
| `.env`   | 只在服务器维护（`/etc/nongyu-track.env`）；日常发布**不同步**本机 `.env`、**不覆盖** SQLite |

### 1.3 非目标

- 本机保存文件即自动 scp（须 push `main` 或手动 dispatch）
- 在服务器上日常改源码热更
- 把业务 Node 与 Track **强制一次全量发布**（按路径独立 job）
- 为 IP 申请普通 90 天域名证书
- 因仅改动 `apps/nongyu-go-track-server/**` 而触发生产发布

## 2. 拓扑

```text
公网客户端（App Telemetry / Node BFF）
    │  HTTPS  https://<Track公网IP>/
    ▼
Nginx :443（IP 证书）  +  :80（ACME；443 未放行时仍反代业务）
    │  HTTP  127.0.0.1:8081
    ▼
nongyu-track（systemd → Node dist）
    │  文件  /var/lib/nongyu-track/track.db
    ▼
本机 SQLite（WAL）
```

业务 Node 在**另一台机**：Track 的 `NODE_INTERNAL_BASE_URL` 填业务 Node 公网 HTTPS 根（无尾斜杠）。业务 Node 的 `TRACK_BASE_URL` 填 Track 公网 HTTPS 根。双方 `INTERNAL_TOKEN` 对齐。禁止把对端配成 `127.0.0.1`。

## 3. HTTPS 绑 IP

与业务 Node 现网相同：

| 项       | 现网约定                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| 档案     | ACME `shortlived`；有效期约 **6 天**                                                                                    |
| 校验     | HTTP-01（webroot `/var/www/acme`）                                                                                      |
| 客户端   | `/root/.acme.sh/acme.sh`                                                                                                |
| 证书文件 | `/etc/nginx/certs/<公网IP>.fullchain.pem` 与 `.key`                                                                     |
| 续期     | crontab：`acme.sh --install-cronjob` 写入每 6 小时检查；输出 `/var/log/acme-cron.log`；成功后 `systemctl restart nginx` |
| 防火墙   | 公网 **80、443**；80 必须保留给 ACME                                                                                    |

客户端 Base URL：`https://<Track公网IP>`（无尾斜杠）。RN：`EXPO_PUBLIC_TRACK_BASE_URL`。

## 4. 推荐发布路径（日常）

日常：本机 `pnpm --filter nongyu-node-track-server test` / 手工验后 push `main`，由 [GitHub 持续交付](../common/GitHub持续交付.md) 构建 Node Track 并安全重启。不覆盖 SQLite、不同步 `.env`。

应急：

```text
本机改代码 → 本机 test / 手工验
    → powershell -File scripts/deploy-nongyu-track.ps1
    → pnpm filter 构建 dist
    → 发布到 /opt/nongyu-track（见脚本）
    → systemctl restart nongyu-track
    → SSH 上回环 curl http://127.0.0.1:8081/health
```

不上传：`.env`、`*.db`、源码树整仓、Windows 非目标产物。

### 4.1 本机命令

```powershell
powershell -File scripts/deploy-nongyu-track.ps1
```

跳过构建：`-SkipBuild`。只上传不重启：`-SkipRestart`。

## 7. 装机 / 切到 Node（摘要）

首次装机（历史 Go）或切 Node 时：

1. 确保用户/目录：`/var/lib/nongyu-track`、`/var/backups/nongyu-track`、`/var/www/acme`。
2. `/etc/nongyu-track.env`：`HTTP_ADDR=127.0.0.1:8081`、`DB_PATH`、与业务对齐的 `JWT_SECRET` / `INTERNAL_TOKEN`、`NODE_INTERNAL_BASE_URL=https://<业务Node公网IP>`。
3. Track 机安装对齐版本 Node + 编译 `better-sqlite3` 所需工具链；发布到 `/opt/nongyu-track`；unit 见 `apps/nongyu-node-track-server/deploy/nongyu-track.service.example`。
4. **切换前**冷备 `track.db`；停 Go → 启 Node → 回环 `/health`。
5. Nginx / 证书若已就绪可不动；业务 `TRACK_BASE_URL` 与 App `EXPO_PUBLIC_TRACK_BASE_URL` 仍指向 Track 公网根。

详细切换步骤见 `plans/埋点服务迁移至Node.md` Phase F。

## 8. 安全

1. 禁止把 root 口令、私钥、`track-deploy.env`、服务器 `.env`、`服务器连接信息.md` 提交到 git。
2. 聊天中出现过的口令视为已暴露：公钥登录可用后应在云控制台轮换 root 密码；Agent 默认不改密。
3. 生产 SQLite 与备份目录权限收紧。
4. Admin 查询仍走业务 Node BFF，不要把 `INTERNAL_TOKEN` 下发到 App。
