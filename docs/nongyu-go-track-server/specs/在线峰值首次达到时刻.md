# Spec：在线峰值首次达到时刻

| 项       | 内容                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| 应用     | `apps/nongyu-go-track-server`；双实现 `apps/nongyu-node-track-server` 必须同步，禁止口径漂移 |
| 需求类型 | **业务**                                                                                     |
| 消费方   | BFF `nongyu-node-server` → 管理端数据大屏 KPI                                                |
| 上游     | 现有 30s `BumpPeak` / `bumpPeak` 采样；`daily_metrics.online_peak`                           |
| 管理端   | `docs/nongyu-web-admin/specs/管理端玻璃拟态排版与峰值时刻.md`                                |
| 状态     | **已实现**                                                                                   |

---

## 1. 背景

**Why**：管理员要知道「今天哪个时间点同时在线最多」，现网只有峰值人数。`daily_metrics.updated_at_ms` 在每次采样 upsert 时都会刷新，不能当峰值时刻。  
**What**：峰值**升高**时记下首次达到该值的 UTC 毫秒时间戳；overview 透出；趋势接口不改。

---

## 2. 目标

1. 新增 metric_key：`online_peak_at_ms`（值为 Unix 毫秒，UTC）。
2. `BumpPeak` / `bumpPeak` 仅在峰值**严格升高**（含从无到有且 sample > 0）时写入该时刻。
3. `GET /v1/admin/overview` 的 `data` 增加 `online_peak_at_ms: number \| null`。
4. Go Track 与 Node Track 行为一致。

---

## 3. 边界（非目标）

- 不改采样周期（仍约 30s）、不改 `CountOnline` / presence。
- 不改 `GET /v1/admin/metrics/trend`（仍按日、只返回人数）。
- 不回填上线前的历史峰值时刻。
- 不在 overview GET 上写库（避免只读接口副作用）。
- 不把时刻格式化成字符串（格式化在管理端，业务时区）。

---

## 4. 详细需求

### 4.1 存储

沿用 `daily_metrics(stat_date, metric_key, metric_value)`，不新表、不加列。

| metric_key          | metric_value 含义                      |
| ------------------- | -------------------------------------- |
| `online_peak`       | 该业务日最高同时在线（已有）           |
| `online_peak_at_ms` | 首次达到当前 `online_peak` 的 UTC 毫秒 |

无行或未写过时刻时，视为「未知」。

### 4.2 写入规则（BumpPeak）

输入：`date`、`sample`（当前在线）、`nowMs`。

1. 读当前 `online_peak`（无行视为不存在）。
2. **sample > 当前峰值**（无行且 sample > 0 视为升高）：
   - 写入 `online_peak = sample`
   - 写入 `online_peak_at_ms = nowMs`（覆盖旧时刻，因为这是新峰值的首次达到）
3. **sample == 当前峰值**：不改 `online_peak`，**不改** `online_peak_at_ms`（并列取首次）。
4. **sample < 当前峰值**：两者都不改。
5. **无行且 sample == 0**：可写入 `online_peak = 0`，**不写** `online_peak_at_ms`（尚未形成有意义峰值）。
6. 禁止在「峰值未升高」时用 `nowMs` 刷新 `online_peak` 的 `updated_at_ms` 来冒充峰值时刻。未升高时允许完全跳过 upsert。

### 4.3 Overview 契约

`GET /v1/admin/overview?date=` 的 `data` 增补：

```ts
online_peak_at_ms: number | null; // UTC ms；未知为 null，禁止缺字段当 0
```

**今日 live**（与现网 `online_peak` 同口径）：

- `online_peak = max(stored_peak, CountOnline())`
- 若 `CountOnline() > stored_peak`：`online_peak_at_ms = 本次请求的 now`（峰值正在发生；不在 GET 落库，约 30s 内由采样任务持久化，时刻可能差一个采样间隔）
- 若 `CountOnline() <= stored_peak`：`online_peak_at_ms = stored_at`（无行则为 `null`）

**历史日**：`online_peak` 仍只读 metrics；`online_peak_at_ms` 有则返回数字，无则 `null`。

今日 live 缓存（若仍使用）必须把 `online_peak_at_ms` 一并纳入缓存对象，避免只缓存人数。

### 4.4 双实现

| 位置                                                         | 必改          |
| ------------------------------------------------------------ | ------------- |
| Go `BumpPeak`                                                | 写入规则 §4.2 |
| Node `bumpPeak`                                              | 同上          |
| Go / Node `handleOverview` + `liveTrendValue` 的今日峰值时刻 | §4.3          |
| 接口文档 `docs/nongyu-go-track-server/接口文档.md` §5.1      | 同步字段      |

`liveTrendValue(..., "online_peak")` 可仍只返回人数；时刻在 overview 组装，不必塞进 trend。

---

## 5. 业务流程

```
每 ~30s CountOnline → BumpPeak
  sample > peak → 写 peak 与 at_ms
  否则 → 不动 at_ms

GET overview?date=今天
  peak = max(stored, liveOnline)
  at  = liveOnline > stored ? now : stored_at|null
```

---

## 6. 验收标准

1. 峰值从 10 升到 12：`online_peak_at_ms` 变为本次采样时刻；之后多次 12 不改时刻。
2. 从 12 降到 8 再回到 12：时刻仍是第一次到 12 的时间，不是回升时间。
3. 历史日无 `online_peak_at_ms` 行：overview 该字段为 `null`，人数仍可用。
4. 今日 live 高于已存峰值时，overview 人数用 live、时刻用请求时刻；人数与现网 `max(stored, live)` 一致。
5. Go 与 Node 行为一致；相关单测覆盖 §4.2 升降与并列。
