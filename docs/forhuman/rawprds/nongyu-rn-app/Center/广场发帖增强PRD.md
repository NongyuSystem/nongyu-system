## 1. 背景

农屿广场由统一 `posts` 表 + `post_type`（announcement / feedback / courtyard）承载公告、反馈墙、大院三类内容。一期已落地三区列表、详情计阅读、纯文本发帖、删帖、我的帖子与首页公告联调，**发帖能力刻意压到最小**：

- App 侧 `ComposeScreen` 只有 subtype 三选一 + 标题（maxLength 200）+ 纯文本正文，无字数统计、无草稿、无键盘避让、无退出确认。
- 后端 `POST /api/app/posts` 只校验 `content: min(1)`、`subtype: string 1-32`：**无 subtype 白名单、无正文长度上限、无发帖频率限制**，与前端约定（feedback/suggestion/bug、life/study/other）存在契约漂移。
- **完全没有图片通道**：Node 无 multer / S3 / 静态目录，`express.json limit 2mb` 也不支持 multipart；`posts` 表无图片字段。
- **完全没有编辑能力**：只有 `updateAnnouncement` 服务管理端公告，用户帖发布后不可改。

一期 Spec `docs/nongyu-rn-app/specs/广场功能.md` §3 把「图片/音频」「用户编辑已发帖」明确列为非目标——**这是范围裁剪，不是遗漏**。本期把这部分能力补上。

---

## 2. 需求概述

### 2.1 发帖体验增强

- 标题与正文补**字数统计与上限提示**，正文上限与后端对齐（5000 字）。
- 发帖页接入**键盘避让**（复用广场已有的 `useComposerKeyboardInset`，当前仅详情页在用）。
- 有未发布内容时，返回需**二次确认**，不静默丢内容。
- **发布中禁用输入与按钮**，防重复提交；失败保留已填内容并可直接重试。
- 错误提示按后端业务码**分类展示**（校验类 / 频率类 / 凭证类各自文案），不再一股脑透传服务端 message。

### 2.2 发帖草稿（本机）

- 输入防抖自动落盘，按 `postType` 分键；编辑模式草稿与新建草稿分键。
- 再次进入发帖页提示恢复；发布成功或用户明确「丢弃草稿」后清除。
- 仅本机，不跨设备、不入库、不进版本库。含图片时只存**已上传成功的对象 key**，不存本地临时文件路径。

### 2.3 图片附件

- 反馈墙与大院帖子**都可带图**，**最多 9 张**。
- 单张**服务端硬限 5MB**；前端上传前压缩（最长边 2560px、JPEG quality 0.8）。
- 允许格式：`jpg` / `png` / `webp` / `gif`。
- 存储走**自建 MinIO（S3 兼容）**，Node 通过 S3 SDK 读写；对象 key 形如 `posts/{yyyy}/{MM}/{uuid}.{ext}`。
- 列表卡片显示图片数量角标；详情以九宫格展示，可点开放大。
- 上传支持单张重试、缩略图预览与删除；发布时只提交成功上传的对象 key。

### 2.4 编辑已发帖

- **发布后 24 小时内**，作者可编辑自己帖子的标题 / 正文 / subtype / 图片，**次数不限**。
- **公告不可编辑**；他人帖不可编辑。
- 编辑窗口以**服务端判定**为准（返回 `canEdit`），前端不按本地时间自行推导。
- 详情与列表展示「已编辑」标记。
- 反馈墙帖子编辑后，**同步更新**对应的 GitHub Issue 标题与描述；同步失败只记日志，不影响编辑响应。

### 2.5 后端校验补强

- `subtype` 改为**按 postType 分桶的白名单枚举**，与 RN 端 `constants/subtypes.ts` 同源。
- `content` 补长度上限（5000）与非空 trim 校验。
- `images` 校验：数组、≤9、每项必须是本桶前缀下的合法 key（防外部 URL 注入）。
- 发帖与编辑加**按用户维度的频率限制**。
- 列表/详情回参补 `images`、`editedAt`、`canEdit`（App 与 Admin 两侧）。

### 2.6 管理端审核

- 管理端帖子列表/详情可查看图片与「已编辑」标记，便于审核。
- 不改既有鉴权、筛选与排序行为。

## 3. 澄清结论（grill）

| 项         | 结论                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 需求分类   | 业务需求                                                                 |
| 完善范围   | 体验增强 + 图片附件 + 编辑 + 校验，四项全做                              |
| 后端动不动 | 前后端一起动，新写 Spec                                                  |
| 图片存储   | **自建 MinIO（S3 兼容）**，不引入阿里云 OSS、不做本地磁盘方案            |
| 图片范围   | 反馈墙与大院**都可带图**                                                 |
| 图片数量   | **最多 9 张**                                                            |
| 图片大小   | 单张 **≤5MB**（服务端硬限）+ **前端压缩**（最长边 2560px / JPEG q0.8）   |
| 图片格式   | jpg / png / webp / gif                                                   |
| 编辑窗口   | 发布后 **24 小时内不限次数**                                             |
| 编辑范围   | 标题 / 正文 / subtype / 图片；公告不可编辑；仅限本人                     |
| 已编辑标记 | 详情与列表都展示                                                         |
| Issue 同步 | 反馈墙编辑后同步更新 GitHub Issue 标题与描述                             |
| 体验项     | **全量套餐**：字数统计、草稿、键盘避让、退出确认、错误码分类、防重复提交 |
| 后端校验   | subtype 白名单 + content 上限 5000 + 发帖/编辑限流                       |

## 4. 非目标（本期不做）

- 不做富文本 / HTML 编辑器，不做视频附件，不做 @提及。
- 不做留言与回复的图片、编辑（`广场回复与留言` 已单独立项）。
- 不做图片 CDN、不做阿里云 OSS、不做复杂的对象生命周期自动清理（只做保留期）。
- 不做公告（announcement）的 App 端发帖与编辑。
- 不做草稿跨设备同步。
- 不做 push 通知（沿用现有前台轮询）。
- 不展示阅读量：App 列表/详情永不展示 `viewCount` / `uniqueReaderCount`（仅「我的帖子」展示 `viewCount`），本期不改变该约定。
- 不回退匿名性：反馈墙与大院对用户彼此匿名，`authorDisplayName` 恒为 `null`；署名仅管理端可见。
